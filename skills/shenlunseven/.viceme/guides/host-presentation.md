# 宿主支付展示

这是免 CLI 与 CLI 共用的支付展示规则。只使用实际返回的字段，由 Agent 确认当前宿主明确支持的能力；环境识别只提供偏好，不能把 Codex 终端版当成 Codex Desktop。调用方规定的展示边界（例如只允许平台内展示）仍然有效。

## 数据与通用规则

- `paymentPresentation.imagePath` 是本地 PNG 的绝对路径，`imageChatSrc` 仅用于明确支持 `local-file://` 的宿主，`widgetPath` 是本地 HTML。字段缺失时不要编造路径。
- `checkoutUrl` 和 `checkoutImageUrl` 位于输出外层，不在 `paymentPresentation` 中。有 `checkoutUrl` 时始终写成可点击的 Markdown 链接；账号订单只有 `paymentUrl` 时使用其原值，并保留同账号登录要求。图片不能替代链接，商品详情页不能替代订单支付页。
- 同一回复正文中，同一订单只嵌入一张二维码图片。本地图片与 HTTPS 图片是互斥候选；只有所选通道不可用或明确失败时切换，不额外追加备用二维码。支付页预览可以与单张聊天图片同时展示。
- 不假设任何聊天都能渲染图片。只使用宿主已声明的图片格式和实际存在的展示工具；有浏览器工具不代表支持本地 HTML 或 `file://`。某个通道失败时，遵守宿主限制，改用另一个独立获准的通道。
- 直接展示返回的 PNG 或 HTML，无需将其读取为文本；安全检查需要时可以查看源文件。不要把 HTML 贴进聊天，支付不要调用 `show_widget`，不得重画二维码、猜补 URL 或向第三方上传支付数据。

## Codex Desktop

- 宿主明确支持本地绝对路径图片且返回 `imagePath` 时，优先在正文单独一行写 `![微信支付二维码](<imagePath>)`，将占位符替换为实际绝对路径。不使用 `local-file://`。
- 同时保留官方支付链接。实际提供 `open_in_codex` 工具时，调用它，以 `target.type=browser` 打开返回的 `checkoutUrl`；账号订单则使用返回的 `paymentUrl`。使用当前任务，不指定其他任务。不能只写“打开支付页面”链接来代替工具调用。
- 本地图片不可用或明确失败时，才使用宿主允许的 HTTPS 图片通道嵌入 `checkoutImageUrl`。不要下载远程图片来绕过宿主显示限制。
- 没有官方支付 URL 时，只能把 `widgetPath` 交给明确支持本地 HTML 的工具；不要假定 `open_in_codex` 能打开本地 HTML。没有内置浏览器工具时保留图片及可点击链接，不声称已打开页面。工具返回 queued 只表示已排队，不等于页面已加载。

## WorkBuddy

优先本地图片：正文单独一行写 `![微信支付二维码](<imageChatSrc>)`。工具可用时再调用 `present_files([widgetPath])` 打开 HTML；不要把 imagePath 或 PNG 交给 `present_files`。没有该工具时仍可展示聊天图片。只有本地图片通道不可用或明确失败时才改用受支持的 HTTPS 图片，同时保留官方链接。

## 豆包工作

优先在工具可用时调用 `present_files([widgetPath])` 投递 HTML，不把 PNG 交给该工具，不从平台名称推断聊天图片能力。本地展示不可用时使用独立获准的官方链接和 HTTPS 图片通道；本地展示成功也保留官方链接。

## Codex 终端版、Claude 与未知宿主

优先交付官方链接；HTTPS 图片仅在宿主明确支持时嵌入。明确支持本地图片或页面的工具也可使用，但不假定存在 `open_in_codex`、`present_files` 或桌面预览。不得因为识别到 Codex 或 Claude 就声称有内置浏览器。

## 展示结果与等待边界

先实际交付二维码或可点击的官方支付链接，再由购买流程启动有界等待；不要提前在后台启动等待。链接是支付入口，不是二维码已经显示的证据。仅生成文件、返回工具结果或交付路径不算已展示。只有托管入口不可用且本地图片和页面都无法展示时，才交付现有 `widgetPath` 绝对路径并说明无法展示；仅交付路径时不要启动等待。是否付款和安装成功由购买命令确认，不能从扫码、倒计时或用户自述推断。
