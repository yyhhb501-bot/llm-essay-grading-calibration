把现有微信小程序整理成一套统一、清晰、适合手机长期阅读和写作的界面。重点改善首页入口、作答表单、批改报告和个人中心，再统一其余页面。

## 3. 设计方向

### 3.1 整体气质

面向申论学习的实用工具：干净、克制、文字易读。以浅灰底、白色内容卡和少量橙色强调为基础，用排版和间距建立层次。

- 首屏突出“开始批改”，用户能快速知道下一步做什么。
- 长篇材料、作答和报告优先保证可读性，减少装饰占用。
- 同类按钮、表单、提示、标签和空态保持一致。
- 使用统一线性图标；避免把表情符号当作主要功能图标。
- 使用自己的视觉语言和素材，不复制其他教育产品的标识与界面。
- 不添加虚构的连续学习天数、排名、提分率、会员权益或教师背书。

### 3.2 建议视觉基线

以下是现有配色的整理起点，可以在整套方案内适当调整，并记录最终值。

| 用途 | 建议值 |
| --- | --- |
| 页面背景 | `#F6F7F9` |
| 内容背景 | `#FFFFFF` |
| 主文字 | `#1D2129` |
| 次要文字 | `#4E5969` |
| 弱提示 | `#86909C`，小字需检查实际可读性 |

| 常规正文 | 约 28–30rpx，长文行高约 1.7 |
| 主按钮 | 高约 88–96rpx，清晰区分禁用和加载状态 |

重要信息不能只靠颜色区分。主要触控区域按不小于约 44px 的设计目标处理。不要用过细小字承载材料、评分说明或隐私提示。

## 4. 页面与导航

保留原生底部导航的四项：**首页／批改／解题／我的**。其余页面从现有入口进入。不要增加重复的自绘底部导航，也不要用自绘顶部栏挤压原生导航。

| 页面文件前缀 | 页面角色 | 主要调整 |
| --- | --- | --- |
| `pages/index/index` | 首页 | 一个明确主入口、次级功能、最近记录 |
| `pages/grade/grade` | 作答与提交 | 表单层次、拍照入口、字数与提交状态 |
| `pages/result/result` | 批改报告 | 结果概览、维度、问题定位、修改建议 |
| `pages/chat/chat` | 解题陪练 | 对话阅读、输入区域、快捷提问 |
| `pages/papers/papers` | 内置改编练习 | 套题展开、题目与材料、去作答 |
| `pages/study/study` | 备考计划 | 信息填写、流式计划、按周打卡 |
| `pages/mine/mine` | 我的 | 真实学习数据、功能分组、数据管理 |
| `pages/settings/settings` | 模型与 Skill 设置 | 配置引导、连接状态、进阶项收纳 |
| `pages/history/history` | 历史记录 | 筛选、记录卡、删除与空态 |
| `pages/service/service` | 服务与隐私说明 | 信息分段、接收方、AI 与数据说明 |

核心路径：

1. 未配置用户：首页 → 模型设置 → 测试并保存 → 批改。
2. 自带题目：批改 → 填题目与材料 → 输入或识别作答 → 提交 → 报告 → 历史回看。
3. 练习用户：内置改编练习 → 去作答 → 自动带入对应内容 → 提交 → 报告。
4. 解题与计划：现有解题入口／备考计划入口 → 真实生成内容 → 本机保存与回看。

## 5. 各页设计要求

### 5.1 首页

- 顶部使用产品名与一句简短说明，说明当前提供申论专项辅助。
- “开始批改”作为主行动；练习、解题、计划等使用现有入口与跳转。
- 每日语录降低视觉优先级，避免占满首屏。
- 最近记录展示真实标题、类型、时间与摘要；无记录时给出开始写作入口。
- 保留 `onEntranceTap`、`onGoGrade`、`onViewAll`、`onRecentTap` 以及相应 `data-*`。

### 5.2 批改页

按“题目与类型 → 材料 → 我的作答 → 提交”的顺序组织。参考答案作为可选辅助区域，清楚说明不替代材料依据。

- 保留题型选择、题目、材料、参考答案、作答五类输入及已有校验。
- 必填项明确标识；无材料时的评分限制应如实呈现。
- 拍照识别与手动输入放在作答区域，识别后允许用户检查文本。
- 提交前展示字数；提交中按钮有文字反馈并保留原有禁用逻辑。
- 识别中保留取消入口，失败展示现有错误与恢复方式。
- 若折叠材料或参考答案，只增加显示状态；不得因折叠清空内容。
- 保留 `onTypeChange`、各输入事件、`onScanAnswer`、`onStart`、`goSettings`。

### 5.3 报告页

阅读顺序建议为“结果概览 → 训练维度 → 具体问题 → 升级建议 → 原题与作答”。长报告需要清楚的标题、引用与段落间距。

- 保留“五维训练指数（非官方成绩）”的性质说明。
- 根据 `hasScore` 等真实状态展示数据；缺分、拒绝评分或流式未完成时，不补成 0 分或满分。
- 问题卡区分原文引用、问题类型、解释与建议；维度条保留文字说明。
- 保留报告分栏、原题展开、复制、重试、再批改及模型设置入口。
- 保留现有 Markdown 分块与加粗渲染，不把生成正文截成几张固定卡片。
- 流式生成时允许阅读已完成部分，失败时保留已获得的内容与现有恢复动作。
- 保留复制内容中的 AI 标识，不把辅助意见包装为官方阅卷成绩。

### 5.4 解题页

- 用户消息与 AI 消息层次明确，长文可读；AI 身份在界面可见。
- 保留快捷问题、新对话、历史只读提示、继续对话和长按消息操作。
- 输入区域适配键盘、安全区和多行文本；发送状态与已有逻辑一致。
- 保留滚动定位与流式内容，不新增会反复抢走阅读位置的滚动逻辑。
- 可将“名师”等容易引起误解的文案统一为“AI 解题陪练”。

### 5.5 练习页

- 保留“内置改编练习（非原卷）”及摘要版说明。
- 套题标题、年份、题数、展开状态清楚；题目、材料、参考关键词有层次。
- 保留材料节选与全文载入说明，以及 `togglePaper`、`onAnswer` 和题目 ID。
- 不把改编材料、参考关键词改称官方原卷、官方答案。
- 题数读取真实数据；筛选、搜索等新增业务功能另列需求，不做无效控件。

### 5.6 备考计划页

- 保留基础水平、每日时长、目标岗位、考试剩余周数四项设置。
- 生成中、失败、空态、计划正文与按周打卡清楚区分。
- 打卡和进度读取现有本机数据，保留重置确认与复制操作。
- 保留 AI 生成提示；不要展示未实现的每日推送或自动监督。

### 5.7 我的页

- 使用真实批改次数、平均训练指数和对话次数，缺少数据时展示合理空值。
- 分组建议：“学习记录”“工具设置”“隐私与数据”“关于”。
- 模型配置状态可见；历史、计划、服务说明入口容易找到。
- 撤回模型传输同意、删除本机数据、清空历史属于不同动作，保留各自语义和确认。
- 不把本机统计称作账号云端数据，不放虚构头像昵称或已登录状态。

### 5.8 设置页

- 新用户先看到可执行的配置步骤；高级 Skill 设置可收纳到低优先级区域。
- 供应商预设、baseURL、API Key、主模型、视觉模型均保留。
- API Key 输入保持遮蔽；截图、日志和示例中不得出现真实密钥。
- 保留测试连接、保存、清空配置、自定义模型输入与视觉模型清空功能。
- 保留 Skill 启用、编辑、字数限制、保存、导入剪贴板、导出、清空。
- 清楚说明数据会发送至配置的接收方；自定义地址仍要求 HTTPS 和小程序合法域名。

### 5.9 历史页与服务说明

- 历史保留全部／批改／对话筛选、点击回看、长按删除和清空确认。
- 记录卡适配长标题，无记录按筛选类型给出对应行动。
- 服务说明按“AI 能力与限制／数据接收方／传输内容／本机管理／隐私指引”分段。
- 不删减实际数据传输、图片、密钥使用、接收方保存与删除边界等实质说明。

## 6. 公共组件与状态

先统一按钮、输入框、选择器、卡片、标签、消息提示、空态、加载态、错误态，再逐页应用，减少各页重复样式。

每类关键界面至少处理：

| 界面 | 必须覆盖的状态 |
| --- | --- |
| 首页／历史／我的 | 无数据、已有真实数据、长标题 |
| 批改 | 未配置、可编辑、识别中、识别失败、提交中 |
| 报告 | 生成中、完整内容、无分数、出错、记录不存在 |
| 解题 | 首次进入、长对话、生成中、错误、历史只读 |
| 设置 | 未配置、已配置、连接测试中、成功、失败 |
| 计划 | 无计划、生成中、失败、已有计划与打卡 |
| 隐私弹窗 | 阅读、拒绝、同意后继续原操作 |

所有页面保留 `<privacy-dialog id="privacy-dialog" />`。隐私组件可调整排版和样式，但必须保留拒绝入口、查看指引入口、`open-type="agreePrivacyAuthorization"`、`bindagreeprivacyauthorization="onAgree"` 和原有事件关系；不能用普通按钮模拟已授权。

## 8. 账号页面：可选的待接入设计

如本轮提供账号设计稿，采用用户已选的“用户名＋密码”，注册预留邀请码字段。需标记为“待小程序接口接入”，与已实现页面分开交付。

设计可涵盖登录、注册、错误提示、退出与登录后的个人中心；密码找回方案尚未确定，不制作假成功流程。不要保存明文密码，不将网站登录态视为微信小程序登录态，也不要声称已完成 `wx.login`。

真正接入前，需要功能负责人单独确认小程序会话保存、请求鉴权、账号记录归属、合法请求域名和退出清理规则。原有未登录本机记录如何迁移也需要明确规则。未接入前，这些页面不进入正式可用导航。
