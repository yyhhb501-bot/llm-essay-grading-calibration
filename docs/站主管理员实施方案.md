# 站主管理员账号实施方案

日期：2026-10-21。用户要求新建自己的管理员账号以先试用手机网站，已确认没有现有账号。小程序工作继续暂停。

## 范围与顺序

1. OpenCode：`server/auth.mjs` 增加真实角色读取、管理员鉴权；新增 `worker/migrations/0003_account_roles.sql`；`server/auth-local.cjs` 加载新表。build、permission allow，仅上述文件，语法检查。
2. Codex：管理员只读概况接口与一次性本机设置工具，整合 Worker／本机服务。设置页只在 127.0.0.1 提供，密码由用户亲自填写，不打印、不写文件、不发聊天。通过已有 Cloudflare 授权创建账号，不依赖未知邀请码。
3. 页面只做必要的本机设置表单，不扩建用户管理／删除功能；既有网站前端不改。工作者按顺序运行，保留现有改动与网站发布快照。
4. 发布需要用户明确指示；新建账号是用户已请求的生产数据操作。新表仅记录角色，已有账号默认为 member；普通注册不能自行取得 admin。

## 设计

- 独立表 `auth_user_roles(user_id PRIMARY KEY REFERENCES auth_users(id), role CHECK(role IN ('member','admin')))`。
- `publicUser` 返回 id、username、role。角色由数据库查得，不能根据用户名或请求体决定。
- `authorizeAdmin` 在有效会话上检查 admin；普通账号返回 403。
- GET `/api/admin/overview` 仅管理员可读站点账号数／试卷数，作为当前有限管理权限。不是完整管理后台。
- 本机设置工具使用固定站点与固定数据库、同源校验、内存一次性地址／随机确认值、短时限，按已有密码规则派生密码值。SQL 参数只含派生值；不保存明文密码。账号名冲突不覆盖任何账号。
- 管理员不需要邀请码即可首次开通；后续与其他用户一样通过用户名密码登录。试用沿用已有共享模型。

## 验收边界

语法、Worker dry-run、实际角色写入和新账号开通结果分别记录；不声称静态检查等于真实登录成功。设置工具可在用户主动提交时检查本站登录与管理员身份，随后撤销该临时检查会话。没有真实完成则明确报告等待设置。

发布使用当前线上静态资源，不能顺带发布本地网站未上线改动。生产账号不因工具超时、网络错误或重试而被覆盖、降权或删除。
