## 后端契约

- 固定服务地址 `https://shenlundawang.asia`，共享现有账号库及邀请码规则。
- `/api/mp/auth/session` GET；`register`、`login`、`logout`、`password` POST。注册字段 username/password/inviteCode；改密 oldPassword/newPassword。
- 原生接口只接受 Bearer 会话，不以 Cookie 作为原生凭据；网页登录仍只使用 Cookie。注册／登录／改密返回 `{ok,user,token,expiresAt}`，仅原生通道返回 token。
- 原生请求允许无 Origin；有 Origin 时拒绝不匹配来源；不添加宽泛 CORS。HTTPS 必需（本机开发例外），POST 只收 JSON、限制体积、保留限流与密码散列。
- token 为高熵随机值，数据库仅保存摘要、7 天有效、退出撤销、改密撤销旧会话。用户字段仅 id/username。
- `/api/mp/chat` POST 使用原生 Bearer，复用既有共享模型转发；网站 `/api/chat` 的安全条件不放宽。
- 不做验证码、微信身份绑定、密码找回或云端记录同步，不返回任何服务端模型密钥。

## 小程序契约

- 新账号页面 `pages/account/account`，登录／注册／修改密码通过 mode 切换。用户名 3–24 位（中文、字母、数字、_、-），密码 8–128 字符，邀请码必填，遵循实际后端规则。
- `utils/auth.js` 负责固定源的请求、会话保存、登录／注册／改密／退出、失效处理；密码和邀请码不落盘、不记录日志。网络故障不冒充已退出或删历史。
- 登录账号可以调用共享模型；用户已有自带 Key 模式继续支持，账号 token 只发固定账号与共享模型服务，不发自定义地址。
- 允许未登录本机模式：旧 slz_* 数据保持原处，登录后不自动归给新账号。每账号独立配置、Skill、历史、计划。界面明确“本机保存，不跨设备同步”。
- 切换前中止活动请求，卸载旧页面并完成旧账号保存后才切换命名空间；隔离延迟回调与过期响应，清理跨页引用、输入缓存，防止 A 写到 B。
- 退出应撤销服务端会话；失败时明确提示并提供本机退出选择。删除本机数据必须覆盖账号相关缓存和会话，不能退化成只删旧 slz_*。
- 保留所有隐私授权、AI 标识、流式响应与原有页面导航。登录表单说明账号凭据发送至站点；不得显示真实 Key、密码或邀请码。
