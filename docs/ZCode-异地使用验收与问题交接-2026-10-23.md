## 问题 1：线上与本地版本不一致，题库索引少于本地（P1）

复现：分别下载正式域名 `/js/vendor/papers-index.js` 与读取本地 `site/js/vendor/papers-index.js`，在隔离 JS 上下文读取 `window.PapersFullIndex` 键数。

- 线上：53 套，59,096 字节。
- 本地：371 套，426,401 字节。
- 首页 `/`、`js/auth.js`、`js/app.js` 的 SHA256 也与本地不同。
- `js/api.js`、`js/store.js`、`css/site.css`、`js/vendor/paper-catalog.js`、`js/vendor/coverage.js` 本轮比较相同。

影响：不能把本地新增题库与功能当作朋友已经可以在线使用的内容。53/371 是完整题库索引条目数，不是全部目录数、题目数或已核验参考答案数；不能据此断言缺少的所有试卷都已具备可靠完整材料。

建议：先确定正式发布基线与构建清单，核对 app、索引、逐卷 JSON、压缩 bundle 的配套版本。检查旧线上快照是否有意保留，不得直接用整个脏工作区覆盖生产环境。

验收：从明确的发布目录生成资源清单及哈希；线上抽样验证目录→选题→材料加载→去作答预填。题库数量以审核后的发布清单为准，不能为了追求 371 套直接发布不完整内容。用户明确授权发布后，才可部署并核对实际线上资源。

## 问题 2：账号回归断言落后于角色接口（P1，验收阻塞）

运行：`node tools/test-auth.mjs`。

第 7 个 PASS 后，在第 52 行附近 `no token in JSON response` 断言失败：预期字段 `['id','username']`，实际 `['id','role','username']`。角色字段本身不是令牌泄漏；这是接口新增角色后测试未同步，导致本轮后续会话、改密、注销等检查提前中止。

建议：更新测试契约，保留禁止返回会话令牌与密码派生信息的断言；补普通 member、管理员角色及拒绝注册提权检查，不能只删除失败断言。不要为迎合旧测试删掉角色或弱化服务端鉴权。

验收：该脚本完整成功退出；普通用户不能访问管理接口，用户名叫 admin 不自动获得管理员权限，公开注册不能指定管理员角色。

## 问题 3：题库来源校验规则与新增来源不一致（P2）

运行：`node tools/test-paper-catalog.js`，第 9 行来源 URL 正则失败。

本地目录 380 条，其中 4 条 `https://m.aipta.com/article/...html` 不在旧规则允许的两个来源范围；例：`source_aipta_256`，URL `https://m.aipta.com/article/256.html`。

影响：当前目录自检无法通过。该失败只证明校验规则与数据不一致，不能直接推断网站运行崩溃或来源一定无效。

建议：逐条检查四个来源的可达性、题名、年份与材料对应关系，再维护明确允许的来源与路径规则；无依据的内容保持待核验。不得放宽成任意 HTTPS URL 或删除出处检查。

验收：来源测试完整通过，重复 ID、年份、地区覆盖等后续断言也执行；新增来源保留出处和核验状态。

## 待补的线上核心流程验收（P1）

本轮没有可用的已登录验收会话，未读取或复用用户密码，也未借用历史验收证明本次通过。由站主在本地输入密码，或提供用途明确的普通测试账号及邀请码使用方式后执行；密码不得写进聊天、截图、日志或交接文件。

1. 新浏览器注册普通账号，退出后重新登录；刷新恢复会话；注销后受保护接口拒绝访问。
2. 在共享模型设置中测试连接，实测正式 `/api/chat` 返回非空内容、中文流式输出及失败中文提示。`sharedReady=true` 仅检查环境变量存在。
3. 从线上完整题库选一题，检查题干、材料、题型与作答页预填对应；手动输入作答后跑完完整报告，检查分值范围、维度、引用批注、复制和重试。
4. 刷新后回看历史；切换账号不能读取另一账号的历史、计划或模型 Key；注明记录只在当前浏览器。
5. 陪练发送至少两轮，备考计划生成及刷新恢复；图片识别若保留入口，单独验收视觉模型。不要将文本模型短请求成功等同图片识别通过。
6. 朋友在异地手机关闭 Wi-Fi，用 4G/5G 打开正式链接完成注册、批改、回看。再检查微信内置浏览器；记录设备、网络、耗时及错误，不记录密码和 Key。
